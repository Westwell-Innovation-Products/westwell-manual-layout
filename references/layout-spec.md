# 最终版式与表达规范

本规范依据《FMS用户操作指南-西井青蓝配色预览.html》及 `build_brand_preview.cjs --cyan` 的最终确认结果提炼。以下是操作手册的默认规范；本次请求中的明确例外优先。FMS 特定章节和业务术语见独立参考文件，不把 60 页、85 张图或固定章节数量当作通用要求。

## 1. 视觉基准

| 角色 | 最终取值 | 使用边界 |
| --- | --- | --- |
| 正文、主要标题 | `#222222` | 包括封面大标题、章节扉页标题、功能标题；不整体染成蓝色 |
| 主强调色 | `#0047BB` 墨子蓝 | 步骤编号、链接、小标签、按钮名称、一级目录标题 |
| 辅助线条 | `#00B3FF` 跃迁蓝 | 步骤上方短线、扉页短线、页脚短线 |
| 提示卡片色条 | `#2CCCD3` 鳞光蓝 | 左侧 3px 实线 |
| 辅助文字 | `#545859` | 图注、页码等 |
| 一般分隔线 | `#E4E7F4` | 表格、图片框、目录分隔等；不重新加到入口或提示卡片四周 |
| 页面 | `#FFFFFF` | 章节扉页也是纯白，无背景渐变 |
| 页面外背景 | `#F4F6FB` | 屏幕阅读环境 |
| 操作入口背景 | `#FAFAFA` | 4px 圆角，四周无边框，无左色条 |
| 注意事项 / Tips 背景 | `rgba(91,194,231,.08)` | 白纸上的浅青蓝背景，7px 圆角；仅左侧有色条 |
| 正文按钮名称底色 | `rgba(0,179,255,.07)` | 字色墨子蓝，细线边框可保留；不是真实交互按钮 |
| 表头 | 墨子蓝底、白字 | 数据区域白底、浅色分隔线 |

黑色正文与标题是用户对本手册的明确偏好，优先于品牌通用模板中“所有标题使用蓝色”的默认方案。浅色以官方色透明度衍生。小字号文字用深色，不用亮青或亮绿。原始系统截图和正式 Logo 不改色。

### 目录与导航

- 一级章节标题为蓝色，二级标题为黑色；主目录、侧栏和章节扉页内导航一致。二级编号可保留蓝色，不把二级标题文字一起染蓝。
- 扉页导航中的条目属于二级标题，因此为黑色。
- 英文 `Chapter 4` 等章节标签完整单行；给编号列足够宽度，不能仅设置不换行后让文字覆盖后一列。
- 章节页眉显示当前位置，如“第一章 创建船舶”，不是所有页都显示相同的泛称。
- 页码、目录页码和内部引用随分页/编号变化同步。

## 2. 页面、字体与扉页

### 首页封面

- 封面置于目录之前，是独立组件，不能用章节扉页替代。纯白背景，页眉沿用正式 Logo，右侧为项目/手册名称；页脚沿用统一页码与细线。
- 主体在页眉下约 80px 开始，左对齐：产品简称 + 手册名称分行显示，黑色约 57px、1.3 倍行高；下方是约 20px 的英文产品全称或副标题。
- 副标题下保留青蓝装饰短线及短尾线，随后是项目/语言版本和版本日期。右上可沿用浅色细线的四分之一圆弧装饰，不增加大面积背景渐变。
- 项目名、产品名、语言及日期是调用时提供的内容，不写死为 FMS、POF 或样例日期；不自行把编辑当天当作文档版本日期。
- 封面遵循已有样板的上部左对齐构图；章节扉页才使用下述“内容块整体居中”规则。

### 内页与章节扉页

- 默认 A4 纵向，210 × 297 mm；页面左右边距约 16 mm。已有文件的已确认布局优先保持。
- 中文思源黑体优先，英文 Encode Sans 优先；可回退系统可用字体。交付要检查实际加载后的分页，避免依赖在线字体才能正常显示。
- 正文约 15–16px，行高约 1.7–1.75。功能说明为常规字体、黑色，不用灰色斜体小字。辅助图注约 12px、居中。
- 章节扉页标题约 40px，正文二级功能标题约 24px，三级标题约 20px，段内小标签约 14px。英文标题较长可适当调整字号或自然换行，不挤压编号与标题；`Chapter N` 标签不得拆开。
- 扉页内容块整体水平与垂直居中，块内左对齐。建议内容宽度约 610px，标题下有细分隔线与短强调线，下方为简介和小节导航。少量留白组织层级，不把文字堆在左上角。
- 扉页是本章简介，不塞入实际操作步骤；具体步骤放功能页。背景纯白，不再加蓝、绿或暖色背景渐变。封面已有装饰短线不属于扉页背景渐变，不因本规则扩大修改范围。
- 同一类卡片、标题、图注保持一致；不要因单页密度随意修改整体字号。

## 3. 内容顺序与适用范围

功能介绍页顺序固定：

**功能标题 → 操作入口 → 一句场景/用途说明 → 操作步骤与配图 → 注意事项 / Tips。**

- 优先使用已有场景说明，没有时补一句简单准确的话，回答“何时用、做什么”。避免标题复述和没有信息的套话。
- 说明在入口卡片后，使用常规正文字体。
- 纯定义、作用、使用场景或流程介绍页不强行添加入口或步骤模块。
- 已有概念说明放在相关操作之前；是否独立成节由内容量和用户要求决定，不一律增加“概述”章节。
- 同一功能跨页时，后续页直接承接内容，避免重复整套入口、功能说明和“操作步骤”标题。

| 内容 | 表达形式 |
| --- | --- |
| 可执行操作动作 | 使用操作步骤，01、02 连续编号 |
| 定义、作用、规则 | 段落、说明列表或表格 |
| 常用场景 | 场景描述，必要时 a、b、c 列表 |
| 场景中的正确处置 | 可用“准确操作”小标题，不必编号 01 |
| 操作方式/入口范围 | 普通说明，例如“可单台或批量操作” |
| 限制、风险、后果 | 注意事项卡片 |
| 技巧、补充说明、跨章节参考 | Tips，独立卡片或并入相关卡片 |

标题要准确指向动作或内容。例如创建操作写“创建船舶计划”，而非含糊的“船舶计划”。段内小标题无末尾冒号；列表中的分类短语加粗，随后解释为常规字重。已有小标题或卡片标题时，正文不再重复“场景描述：”“正确操作：”“注意：”“但注意：”等标签。

## 4. 图文与步骤

- 始终先写操作文字，再放对应图；图注置于图片下，图片和图名都居中。
- 步骤编号和配图严格对应。一个步骤可配多张图；入口、按钮、结果截图可并排组合，保持顺序清楚。
- 用途说明不因配了一张图就变成操作步骤。步骤应描述动作，必要时包含入口和已知结果；不凭猜测补齐业务行为。
- 尽量保持同一步文字与对应图同页；不要把步骤 02 的图错配到步骤 01。
- 保留截图内容、比例和实际按钮名称。布局可缩放图片，但必须能够阅读关键区域；不要为凑页数删图或裁掉信息。
- 图片可点击放大是 HTML 手册的有用能力，已有时保留；PDF 不承诺具备网页交互。

## 5. 注意事项与 Tips

- 两者均使用浅青蓝卡片、7px 圆角；只有左侧 3px `#2CCCD3` 色条，上/右/下边框为零。
- 注意事项：标题为“注意事项”，使用线框圆形感叹号，不用灯泡。
- Tips：标题统一为 `Tips`，保留线框小灯泡；不要换成 emoji、实心灯泡或感叹号。
- 相关补充内容与章节链接放进对应卡片，不悬挂在卡片外。独立 Tips 也可使用相同卡片。
- 同一卡片内可有注意事项和内嵌 Tips；不要因合并而丢失原文、链接或独立含义。
- 注意事项属于正文信息，不自行添加未经确认的业务警告或删除仍有效的内容。

## 6. 分页与交付

- 关系紧密且内容较少的相邻小节可同页。优先减少无意义空白，避免每个小标题都强制新页。
- 先调整段间距、图片组合与合理尺寸，再决定拆页。不要以缩小到难读的字体、隐藏溢出或删除内容来满足固定页数。
- 中英文分别验证；英文可以独立调整间距和分页，不强求与中文页数完全相同。
- 输出类型由请求决定。只改 HTML 时不自动覆盖原 PDF；要求多种格式时，以同一内容版本导出并核对。
- 本次任务只更改配色时，不同步改业务内容、术语或章节结构；本次只改某类卡片时，不影响其他组件。
